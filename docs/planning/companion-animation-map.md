# Companion animation name map

Updated: 2026-11-14. **Owner-approved name allocation; shared runtime registry implemented.**

This applies the requested reuse-first method to the [action vocabulary](companion-action-design.md). Every one of the 122 registered action videos and 27 stickers has a disposition below. Existing Room names are aliases, not extra movies. No screenshot, frame extraction, video playback or new media production was used for this allocation.

The owner approved connecting this allocation to the existing players. The generated runtime registry indexes all rows; actual Body phases, admitted presentation hints and saved item metadata select compatible rows. Conditional/reserve slots do not create new activities or goods. Dedicated gaps remain explicit. This is not artistic or installed acceptance. The [implementation record](../validation/mapped-playback-2026-11-14.md) owns code checks and the current uninstalled candidate.

## Reading the mapping

- **Direct**: matching name; the title does not prove every entry/exit gesture exists inside the file.
- **Combined**: reuse whole clips in the real phase order, share a common main clip, or accompany the real current action with factual text/stickers.
- **Proxy**: nearest related name, with the exact missing detail explicitly recorded.
- **Blank**: leave the dedicated movement empty after considering common reuse; continue to show truthful activity/status.

`A → B` means sequencing, not layering two full-body characters. `RETURN` means return to the same still-valid activity and progress. Text/stickers accompany the body; existing whole-character movies are not assumed to expose swappable eyes, hands, cups or food. No arbitrary cropping, reversal, speed change or prop replacement is assumed. Right-turn reuse explicitly proposes horizontal mirroring of the named left-turn clip on both surfaces together; the shared managed players now apply the same explicit mirror flag when a real route admits `move.right`.

An ending idle in an example is used only if the actual next state is quiet; otherwise enter the real next/resumed clip directly. Attention/entry feedback may be omitted when incompatible. Interaction facts and effects never wait for the animation. These combinations do not prescribe a daily routine.

Only real phases/context admit a sequence. A clip boundary does not drink again, consume another item, perform another garden job, settle a transaction, confirm reading or choose a new goal. Incidental feedback cannot erase her actual mood or willingness. Fixed/random rotation among the rows is not authorized.

## Runtime boundaries

- Owner-confirmed sleeping feed/water attempts ask for wake first and perform no eating/drinking effect. A trip to bed is not sleep entry; a quiet wait is not waking.
- Clip changes never admit goals or settle physical/economic effects. Entry/exit examples are skipped when the actual domain is already in the main phase. Sleep does not end when its movie loops. A real phase change may truncate a cosmetic sequence; unplayed tails never delay or resurrect the activity.
- Real catalog-food consumption saves its optional visual slot in the existing Body checkpoint. No item-name/chat-prose guessing, new shop goods or old baifan workflow is introduced. Component-only clips retain a proxy/static gap.
- Quiet rest may use one actual named feeling. Multiple/unknown feelings keep a compatible neutral posture; no invented priority or rotation. Busy interactions retain CURRENT and use committed fact text/registered stickers.
- Actual travel, interruption/return, reading offers and restart retain their original owners. Ordinary shared window dragging does not use the independent lifted-body movie.
- The build reads existing container timing without decoding frames; actual file durations define visual boundaries. An early-ended one-shot holds its final frame on the original boundary timer, including hidden/resume, without repeating its tail. This changes no allocation or media bytes.
- All 42 legacy Room keys resolve to the same installed media set. The 32 duplicate Room WebMs are source/provenance inputs only; original posters and notices remain packaged.

## Coverage

- 122 action videos and 27 stickers indexed individually.
- 127 proposed slots: proxy 29, combined 31, direct 55, blank 12.
- 69 distinct videos selected by these core/detail slots; the other 53 have specific optional/status/context roles in the reverse index. They are not scheduled automatically.
- 42 Room clip keys listed separately as aliases; 3 food PNG components retained as composition support.

A combined/proxy row may retain a dedicated submotion gap. That gap is not silently counted as an exact match. No new generation list is ordered by this document.
